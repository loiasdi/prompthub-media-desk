# 内容级视频提示词、素材管理与自动发布方案

日期：2026-11-16
适用项目：PromptHub MediaDesk（prompthub-media-desk），基于当前 2.6.2 实现
文档状态：产品与技术设计；本文描述新增能力，不代表已实现。

## 1. 目标与范围

每篇内容成为一个完整的制作与发布档案：脚本、分镜、AI 视频提示词、图片、音频、视频成片和发布记录都归属于该内容。后续发布时，打开这篇内容就能找到并使用正确的文件。

用户的核心操作链路：

> 打开内容 → 生成视频提示词 → 在外部工具制作视频 → 将视频、图片、音频导入该内容 → 选定发布素材 → 立即发布或定时自动发布 → 查看结果。

本次范围：

- 在内容详情中增加视频提示词生成、编辑、展示和导出。
- 在内容详情中增加文件夹及视频、图片、音频的导入、预览与整理。
- 将已有 AI 生成图片纳入该内容的素材管理。
- 建立发布版本，固定标题、正文、封面及成片，支持手动导出和平台自动发布。
- 在现有内容管理、排期页面显示素材准备情况和发布结果。

保持现有五个主导航，不新增独立素材库页面。第一版素材属于单篇内容，不建设跨内容共享素材库、复杂标签体系、剪辑时间线或视频生成服务。导入多个视频或音频不会自动剪辑、混音，自动发布使用用户选定的完整成片或有序图片集合。

## 3. 页面设计

### 3.1 内容列表

保持看板和表格，卡片增加紧凑摘要，例如：

> AI 工具测评 · 草稿
> 视频 2 · 图片 5 · 音频 1 · 已选成片
> 小红书：待手动发布 / YouTube：11 月 18 日 20:00 自动发布

卡片快捷菜单增加「素材」「发布」，直接打开详情的对应标签。表格增加「素材」「发布」列；支持按“缺少发布素材、可发布、定时中、发布失败”筛选，具体判断由发布面板的同一套规则计算。

不在卡片上展示所有文件。点击后进入该内容完整档案。

### 3.2 内容详情

沿用当前 Studio，右侧增加标签切换；左侧继续使用当前内容的对话助手。

```text
← 返回内容     AI 工具测评                保存 / 发布

左侧：对话助手       右侧：
                    [稿件] [视频提示词] [素材 8] [发布]

                    当前标签内容
```

默认进入「稿件」，保留已有脚本、封面和分镜展示。从列表素材入口进入时直接打开「素材」；从日历发布入口进入时直接打开「发布」。切换标签不丢失已保存编辑。

对话可以修改提示词和素材名称，但不通过普通模型输出直接发起外部发布。发布由明确的按钮或用户预先启用的定时任务执行。

### 3.3 素材标签

```text
当前内容 / 素材                         导入文件  导入文件夹

文件夹                文件网格或列表
全部                  [成片 v2.mp4]   已选发布视频
视频                  [试做 v1.mp4]   制作素材
图片                  [封面.jpg]      已选发布封面
音频                  [配音.wav]      配音

底部：8 个文件 · 总计 428 MB             导出内容文件夹
```

第一版提供「视频、图片、音频」三个固定分类目录；「全部」是聚合视图，不是另一个磁盘目录。每类支持一层自定义子文件夹，满足“参考、过程、成品”等简单整理需求；同篇内容内可以移动、重命名和排序。

卡片展示名称、缩略图或类型图标、大小、时长、用途和导入时间。支持按名称搜索、按时间或名称排序、批量移动和删除。

## 4. 内容文件夹与媒体导入

### 4.1 文件归属

- 从某篇内容导入的文件只归属该内容，不额外创建灵感卡片。
- 原文件复制到工作台管理目录，之后移动或删除原文件不会影响内容。
- 界面重命名与移动只修改元数据，磁盘文件使用稳定 ID，避免路径变更导致引用失效。
- 文件名允许重复，通过素材 ID 区分。相同内容、相同文件哈希再次导入时提示已有文件，默认复用已有素材记录。
- 第一版不做跨内容物理去重；跨内容复用可以再次导入，降低删除和归属管理复杂度。
- 当前内容的导出文件夹与工作台内部存储分开管理，不能把已导出的副本视为内部文件。

### 4.2 导入入口

支持文件选择、多文件拖入、文件夹导入，以及把文件拖到某个分类目录。音频、图片和视频按实际类型自动分类；图片拖入视频分类时仍按图片保存，并提示分类结果。

导入整个文件夹时保留文件名和一层子目录，过深层级折叠为可读子目录名。过滤系统隐藏文件，逐个报告不支持的格式。文件夹选择能力缺失的浏览器继续提供多文件选择。

浏览器上传的是客户端选择的文件；工作台管理和“打开文件夹”位于 DSH Host 所在机器。远程访问网页版时，以在线预览和下载为主要入口。

### 4.3 格式和大小

| 类型 | 第一版导入格式 | 展示方式 |
| --- | --- | --- |
| 视频 | MP4、MOV、WebM | 海报帧、播放、进度拖动、时长及尺寸 |
| 图片 | JPEG、PNG、WebP、GIF | 缩略图、大图预览、尺寸；GIF 保留原文件 |
| 音频 | MP3、WAV、M4A、AAC、OGG | 播放器、播放进度、时长和文件信息 |

导入支持不等于浏览器解码或平台发布支持。无法预览时保留文件并显示“当前浏览器无法预览”，提供下载；发布是否支持由目标平台单独校验。

建议默认单文件上限 2 GiB，可在设置中调整；同时受 Host 和部署代理限制。采用流式接收与临时文件，完成后再写入正式记录，避免把视频整体加载到内存。第一版提供单文件重试，不承诺跨重启断点续传。

导入队列显示逐文件进度；一个文件失败不影响其他文件。取消或失败的临时文件定期清理，磁盘不足时显示具体原因。

### 4.4 用途与发布选择

素材用途提供简单选项：参考、封面、配图、分镜图、配音、背景音乐、视频片段、视频成片。用途和文件类型分别保存。

第一版不根据“最新上传”自动决定最终发布文件。用户明确选择「设为发布视频」「设为发布封面」「加入发布图片」，可见地标出已选素材。每个发布目标可以选择不同成片、封面和图片顺序。

配音、背景音乐和视频片段作为制作素材归档。选择它们不会自动合成为可发布视频。

### 4.5 已有图片与删除

- 当前生成封面、配图、分镜图自动登记为素材，带来源和对应分镜标识，现有稿件展示继续引用它们。
- 单张重画产生新素材版本，保留旧版本供查看；现有已固定发布版本不自动切换图片。
- 旧版本素材存在用户主动清理入口，避免无限累积。
- 删除普通素材可撤销；被待执行发布版本引用的素材需要先取消或替换对应版本。
- 已发布记录引用的素材可归档，但不直接物理删除；用户删除整篇内容时提示相关任务和文件，将内容移入回收站并停止未开始的任务。
- 发布已进入提交阶段时先完成结果核对，不能用本地删除表示外部发布已撤销。
- 回收站保留 30 天；清理前再检查引用，发布快照仍在使用的文件不能被自动清除。

## 5. AI 视频提示词

### 5.1 输入与生成入口

「视频提示词」标签的主按钮为「基于当前内容生成」。默认读取最新保存的标题、脚本、分镜、当前写作风格，以及用户明确选定的参考素材。

生成前设置：制作方式、目标模型／通用格式、画幅、目标时长、分段偏好和参考素材。第一版先提供通用结构化方案及一种目标模型的文本输出适配；目标模型适配不意味着已接通视频生成 API。

默认建议“口播配画面”和 9:16，允许用户调整。目标时长与稿件长度明显不符时先提示并提供“按现有脚本规划／先压缩脚本”，不在后台覆盖稿件。

### 5.2 输出与展示

生成结果分为整体方案与生成片段。

整体方案包括视觉风格、人物和场景设定、声音设计及连续性要求。每个片段包含：

| 字段 | 用途 |
| --- | --- |
| 序号、名称、预计时长 | 定位片段与控制长度 |
| 对应脚本段落与分镜 ID | 追溯提示词来源 |
| 参考素材及用途 | 指明人物、场景、产品、音频等参考 |
| 画面与动作、运镜、对白／旁白、声音 | 可独立编辑的制作要求 |
| 最终提示词文本 | 面向外部视频工具，一键复制 |
| 生成结果素材 | 关联外部生成后导入的视频，允许多个版本 |

一个生成片段可以包含多条分镜；分镜图数量不等于视频生成调用次数。用户可以合并、拆分和调整片段顺序，并检查片段时长之和。

逐段支持编辑、复制、重生成和导入视频结果；支持复制全部、导出 Markdown 和 JSON。复制含参考文件名和使用说明；外部工具需要的图片或音频仍需由用户上传，复制文本本身不会传输附件。

### 5.3 版本与关联

- 每份方案有 ID、版本、生成参数和源内容指纹；片段有稳定 ID，不依赖数组序号关联素材。
- 修改稿件、分镜或选定参考素材后，提示“来源已更新”，不覆盖已有方案。
- 更新时提供“更新选中片段”和“另存新版”。第一版采用整体指纹判断过期，片段差异检测可后续优化。
- 重生成保留上一版；用户手改文本可以撤销。
- 文字模型不可用时显示失败和重试入口，不把通用占位文本冒充模型生成结果。
- 第一版参考素材通过用途、说明、尺寸和已有文字信息进入生成请求；只有确认文字模型具备相应输入能力时才发送实际图片／音视频，不声称已分析未送入模型的文件。

## 6. 发布面板

### 6.1 发布目标与账号

一篇内容可以建立多个发布目标；每个目标指定平台、发布账号、内容类型、标题、正文／简介、话题、封面、视频或有序图片列表、公开范围，以及立即／定时发布方式。

“账号”区分数据导入账号与发布授权账号。Monid 导入成功不意味着已经具备发帖权限。发布面板只展示平台适配器返回的真实能力和已授权账号。

不同平台可以覆盖文案和素材，不修改原稿。平台不支持的字段隐藏或明确禁用，不能提交后默默丢弃用户设置。

### 6.2 发布就绪检查

检查从素材记录和实际文件读取，结果分为可发布、需处理、仅手动发布。

- 账号授权和发布权限是否有效。
- 标题、正文及必填平台字段是否满足限制。
- 视频／图文是否满足平台媒体数量、大小、时长、格式、尺寸等约束。
- 选中的本地文件是否存在、已导入完成，且属于当前内容。
- 封面、图片顺序及必要的内容声明字段是否完整。
- 定时时间是否有效；当前平台是否支持原生预约，或需要 Host 本地调度。

检查通过并不保证平台最终审核通过。提交后继续查询状态，界面区分“已提交、平台处理中、已发布、被拒绝”。

### 6.3 发布版本

点击「立即发布」或「启用自动发布」时固定一个发布版本：保存实际文案、素材 ID 与哈希、图片顺序、平台参数、账号和时间。任务只读取该版本，不在执行时临时读取最新稿件。

后续编辑原稿、重画图片或导入新成片不改变排队中的发布内容。用户点击“更新待发布版本”后，替换尚未开始的任务并重新检查；已经开始上传或提交的任务先核对远端状态，再决定后续操作。

第一版通过明确选材和启用动作建立发布意图，不在到点时重复要求确认；用户也可以暂停或取消尚未提交的任务。启用多平台发布时，为每个目标单独显示结果。

### 6.4 手动发布与导出

未接入自动发布的平台提供「复制文案」「下载发布包」「打开内容文件夹」和「记录已手动发布」。发布包只包含当前选定版本所需文件，避免用户从一堆试做文件里挑错。

手动发布支持记录平台链接与实际发布时间，来源标记 manual；自动发布来源标记 adapter。导出或复制成功不改变已发布状态。

完整内容文件夹可另行导出，包含所有素材、脚本、提示词与发布清单。完整归档与平台发布包是两个明确按钮。

## 7. 自动发布执行设计

### 7.1 平台适配原则

优先使用平台官方 API 或已有、具备明确发布能力的服务连接。每个平台适配器声明：支持的内容类型、账号授权方式、媒体限制、上传能力、提交能力、状态查询能力、原生预约能力，以及是否支持远端幂等键或提交结果核对。

本项目现有平台枚举只是内容分类，不能用它推断所有平台均可自动发布。没有验证的适配器显示“仅手动发布”，不提供无效的自动发布开关。

第一版自动发布验收必须落在至少一个真实平台和测试账号上。最终能启用哪些平台，以应用权限和官方接口验证结果确定。平台选择和凭证不影响前面的内容、素材和发布版本设计。

本地直发已实现 [B 站适配器](local-bilibili-publishing-plan.md) 与 [YouTube 适配器](local-youtube-publishing-plan.md)。两者已接入 [DSH 发布入口](local-publishing-entry.md)，默认关闭，各自验证自有应用后再启用。

浏览器脚本模拟点击不作为默认发布实现；如后续采用，需要独立适配和验收，不与 API 发布混为同一能力。

### 7.2 执行链路

```text
发布版本固定
  → 就绪检查
  → 创建持久任务
  → 到期领取任务
  → 再次检查授权与文件
  → 上传媒体并保存远端 ID
  → 提交内容
  → 查询平台处理结果
  → 保存链接、远端 ID 和实际发布时间
  → 更新内容摘要与日历
```

任务状态：draft、queued、preparing、uploading、submitting、processing、published、failed、needs_auth、unknown、paused、cancelled。发布状态与内容创作状态分开。

- queued：已启用，等待执行。
- processing：已被平台接受，等待处理或审核。
- needs_auth：授权失效，重新授权后可继续。
- unknown：提交结果不确定，需要查询或人工核对，不能自动再次发帖。
- failed：已确认失败，允许修复后重试。

### 7.3 调度与离线

任务在 Host 运行，关闭页面不影响执行。平台支持原生预约时优先提前上传并登记预约；否则由 Host 到点执行，并明确显示“需保持 DSH 运行”。电脑睡眠、关机或 Host 停止时，本地任务无法准点执行。

存储 scheduledAt 使用 UTC，另存用户选择的时区用于展示和编辑，默认跟随用户界面时区；夏令时歧义时间需要显示具体偏移。

建议默认补发窗口为 30 分钟：Host 恢复时，窗口内任务自动补执行；超过窗口的任务暂停，显示“已错过排期”，由用户选择立即发布或重新排期。该行为在启用定时发布时展示，可在设置中调整。

已有的“拖到日历”继续表示安排时间，默认不等于启用自动发布。只有选定发布版本并启用后才创建可执行任务。移动已启用任务的时间，应更新同一目标的任务，不新增重复任务；远端已预约的内容需要先更新远端，失败时保留原预约并显示不同步状态。

### 7.4 重试、恢复与防重复

每个发布版本和目标使用稳定幂等键；任务保存上传进度、远端媒体 ID、提交尝试及响应标识。

- 上传及明确可重试错误采用有上限的退避，尊重平台 Retry-After。
- 提交前持久化提交意图；提交返回后立即保存远端结果。
- 超时、连接中断或崩溃后先查询远端状态；结果不确定时进入 unknown，不盲目重复提交。
- 平台无幂等或可靠查询能力时，不承诺绝对只发一次；对不确定结果停止自动重发并提供核对入口。
- 多个 Host 同时运行时，通过事务领取和租约保证同一任务只有一个执行者；租约失效后接管仍需核对远端提交状态。
- 取消本地任务不等于删除平台帖子。平台已经接受的预约需调用远端取消接口；不支持取消时显示实际远端状态。

### 7.5 内容状态与发布结果

保留 idea、outline、draft、ready、published 五个创作状态，新增独立发布摘要。至少一个目标实际发布成功后标记 published，显示“已发布 1/3”；剩余目标仍可排期、执行和失败重试。

日历不能再用 item.status !== published 排除整篇内容，应展示发布目标的待执行任务。全部选定目标完成时显示“已全部发布”。排期成功、上传完成、平台处理中均不能提前标记 published。

手动标记已发布继续保留，但写入正式发布记录并注明来源。多平台指标后续以发布记录关联，不能把多个平台的结果混成同一条远端帖子。

## 8. 数据与存储设计

### 8.1 存储边界

内容、提示词和素材元数据可继续使用现有 state.json；文件保存在工作台本地管理目录。发布版本、任务、发布授权索引和结果记录使用独立 publish.sqlite，作为发布状态的唯一事实来源。

新增 SQLite 是为了事务领取、崩溃恢复及桌面／Web 多 Host 协作，不在本次迁移整个项目数据库。实现前验证 Node >=20、DSH 桌面与 Web 的 SQLite 驱动分发；可优先验证 better-sqlite3 的打包兼容性。该验证属于自动发布里程碑的技术前置条件，不以现有 JSON 队列代替多进程事务。

state.json 中的发布摘要只是缓存，可从数据库重建；发布成功回写 JSON 失败时不能再次发帖。新增加的内容修改与发布快照固定需要宿主协调写入；提交时冻结的文案和文件引用完整保存在数据库快照中。

### 8.2 主要实体

| 实体 | 主要字段 |
| --- | --- |
| Asset | id、itemId、type、role、originalName、displayName、folderId、storageKey、mime、bytes、hash、duration、width、height、source、createdAt、deletedAt |
| AssetFolder | id、itemId、parentId、type、name、sortOrder |
| VideoPromptPlan | id、itemId、revision、sourceFingerprint、settings、globalSpec、segments、createdAt、updatedAt |
| PromptSegment | id、scriptRefs、shotRefs、duration、referenceAssetIds、promptText、resultAssetIds、selectedResultId |
| PublishTarget | id、itemId、platform、publishAccountId、contentType、draftOverrides、selectedAssets |
| PublishRelease | id、targetId、revision、payloadSnapshot、assetSnapshots、scheduledAt、timeZone、idempotencyKey、createdAt |
| PublishJob | id、releaseId、status、attempts、nextRunAt、leaseOwner、leaseUntil、remoteMediaIds、remotePostId、lastError、updatedAt |
| Publication | id、itemId、targetId、releaseId、source、platform、accountId、remoteId、url、publishedAt |

PublishTarget 的编辑草稿属于内容，数据库保存启用后的 PublishRelease、PublishJob 和 Publication。片段结果素材和发布选定素材分别记录，不把“某段采用版本”误当成完整成片。

账号令牌使用系统凭证存储或独立受限文件，数据库只存引用及状态；发布凭证不进入内容 JSON、导出包、模型上下文或普通日志。已有数据采集账号不自动升级为发布账号。

### 8.3 目录建议

```text
$DSH_HOME/media-desk/
  state.json
  settings.json
  publish.sqlite
  files/                         # 保留现有文件
  content/
    <item-id>/
      video/<asset-id>.<ext>
      image/<asset-id>.<ext>
      audio/<asset-id>.<ext>
      thumbnails/<asset-id>.jpg
  tmp/                           # 未完成上传
```

界面文件夹层级由 AssetFolder 记录，不映射为可变磁盘路径。所有文件访问通过素材 ID 定位，服务端核对 itemId 和实际路径归属；不能接收浏览器任意磁盘路径。

### 8.4 兼容与迁移

- 增加独立的内容功能 schema 版本和幂等迁移，读取旧数据时补空集合。
- 将 item.media、production.cover/images/shots 中的本地文件登记为素材，同一文件复用记录，保留原引用以兼容旧界面。
- 外链素材保留为外部引用，不迁移时批量联网下载；用于自动发布前必须下载成本地文件并校验。
- 旧内容没有成片、提示词或发布目标时正常展示空状态；旧 scheduledAt 迁移为待配置计划，不自动发帖。
- 旧 published 内容生成 legacy/manual 记录，缺少平台链接时允许补录，不伪造远端 ID。
- 示例素材与示例发布记录继续标记 sample，不允许示例数据创建真实发布任务。
- 内容撤销不回滚外部发布，也不删除已经发生的发布记录。

### 9.2 接口草案

沿用 /media-desk 前缀与当前 GET/POST 风格；实际实现可以合并，但必须保持内容归属校验和明确返回状态。

| 接口 | 用途 |
| --- | --- |
| GET assets?itemId=… | 当前内容素材与目录 |
| POST assets/upload?itemId=… | 二进制流导入并原子登记；文件名元信息单独校验 |
| GET assets/file?id=… | 按 ID 读取媒体，支持 Range 和 HEAD |
| POST assets/update、assets/delete、assets/restore | 编辑、移动、回收及恢复 |
| POST assets/folders | 创建或修改当前内容目录 |
| POST video-prompts/generate | 创建生成任务，返回任务 ID |
| GET video-prompts/job?id=… | 查询进度与结果 |
| POST video-prompts/update | 保存片段、版本与结果关联 |
| GET publish/capabilities | 平台实际支持的功能与发布账号状态 |
| POST publish/accounts/connect | 发起目标平台账号授权，回调单独处理 |
| POST publish/targets | 保存平台目标草稿 |
| POST publish/check | 对当前目标或固定版本执行检查 |
| POST publish/releases | 固定发布版本 |
| POST publish/start、publish/schedule | 立即执行或启用定时发布 |
| POST publish/pause、publish/cancel、publish/retry | 操作指定发布任务 |
| GET publish/jobs?itemId=… | 获取各目标状态、错误与远端结果 |

| POST content/export | 导出完整档案或指定发布包 |

调用模型、导入文件和创建排期都不产生隐式发布。发布接口使用显式 releaseId，普通 applyOps 和模型生成的操作清单不提供外部发帖指令。

沿用 requestRejection、跨站写入拦截和响应字段过滤。大文件类型验证、文件读取、授权回调及凭证处理是新增接口的实际实现要求。

## 10. 实施顺序与交付边界

### M1：内容素材档案

完成详情标签、三类文件夹、音频支持、批量与流式导入、预览、用途、选定成片／封面、生成图登记、完整内容导出和旧数据迁移。

完成后：打开任意内容即可找到该内容的视频、图片和音频；关闭页面、重启 Host 后仍可访问。

### M2：视频提示词

完成基于当前稿件和分镜生成方案、参考素材关联、逐段编辑与重生成、版本与过期提示、复制／导出、视频结果导入和关联。

完成后：可以从脚本走到提示词，再将外部生成结果放回对应内容和片段。

### M3：发布准备与平台验证

完成平台目标、账号授权、能力检查、发布版本固定、发布包、手动发布记录；并完成首个平台真实接口和 SQLite 分发验证。

完成后：发布时拿到明确选定的素材与文案；已确认首个平台具备后续自动执行条件。此阶段仍不能宣称自动发布已经完成。

### M4：立即与定时自动发布

完成持久任务、调度、平台上传／提交／状态查询、结果记录、失败恢复、防重复、授权过期处理、日历同步及单个平台真实验收。

完成后：至少一个明确支持的平台可以按选定发布版本自动发布。其他平台按适配状态逐个开放；多平台框架不等于所有平台均已接通。

整体方案交付完成必须包括 M4。M1～M3 是可独立评审的中间成果。

## 11. 验收标准

### 内容与素材

1. 同一篇内容导入多个视频、图片、音频后，均在该内容内展示，不创建多余灵感卡片。
2. 重启、切换中英文及桌面／Web 访问后，文件与内容关联保持正确。
3. 大视频上传不会整文件进入 Host 内存；取消、超限、磁盘不足和单文件失败有可理解的结果。
4. 文件夹移动和重命名不影响预览、下载与提示词引用；重复文件可识别。
5. 可以明确识别当前采用的完整成片、封面和图片顺序，试做素材不会混进发布包。
6. 删除和撤销不破坏被固定发布版本引用的文件，清空示例不触发真实发布。

### 视频提示词

1. 生成基于当前保存稿件、分镜和用户选定的参考说明；界面明确呈现实际使用的素材信息。
2. 片段可编辑、复制、重生成、拆分合并，并关联导入的视频结果。
3. 更新脚本后旧方案仍在，显示过期提示；用户手改不会被自动覆盖。
4. 导出包含整体方案、片段、时长、参考素材和源内容版本信息。

### 发布

1. 无授权、缺文件、错误格式或不支持的平台不能被错误标为可自动发布。
2. 任务使用固定快照；执行前修改稿件和导入新视频不会偷偷改变待发布版本。
3. 至少一个平台完成真实账号的立即发布、定时发布及远端结果核对，记录链接和实际时间。
4. 两个 Host 同时运行、执行中重启、上传失败、授权失效和提交超时有相应恢复验证，不盲目重复发帖。
5. 关闭页面后任务继续；Host 停止期间的离线限制和逾期策略准确展示。
6. 单个平台失败不影响其他目标，部分发布成功后剩余任务仍可被找到和执行。
7. 手动导出不算发布成功，平台处理中不算正式发布；外部发布结果不能被普通撤销操作抹掉。

测试重点为数据迁移、文件归属、流式上传、发布快照、跨进程任务竞争、结果不确定恢复和真实适配器联调。保持现有回归测试通过，并完成桌面／Web、窄屏、媒体播放和中英文界面检查。

## 12. 开发前需要落实的具体配置

以下项目不阻塞文档设计与素材、提示词模块，但在自动发布集成前必须落实：

- 首个自动发布平台及账号、对应应用的可用发布权限和接入方式。
- 实际使用的视频生成模型，以确定首个提示词文本适配格式。
- 运行部署方式：长驻 Host 还是主要在本机按需启动；据此确认预约与逾期行为。
- SQLite 驱动的 DSH 打包验证、大文件限制和媒体信息解析依赖。

推荐先实现内容素材档案和提示词，同时验证首个平台发布链路；页面和数据设计以“每篇内容内完成制作、找文件和发布”为中心。
